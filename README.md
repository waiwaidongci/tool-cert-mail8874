# 计量室同轮比对偏差区间

上游同轮比对记录导入后，求每台器具的最窄偏差范围；矛盾组隔离、缺基准待核，上游更新后按组增量重算。

澄岭精密零件厂 · 质量计量室

## 业务问题

计量室把标准器具和工作器具放在同一轮比对中，逐对登记示值差值与允许容差。过去计量员用表格手工推算：

- 上游记录多次更正或撤回后，很难判断哪些器具区间需要随之修正。
- 同一组内的容差链路较长，手工推算的区间往往比真实可行范围更宽。
- 矛盾记录会把整组结果带偏，缺少基准的组又容易被误当成已定结果。

系统把互相有比对关系的器具划成一组，以标准器的偏差为零，求同时满足组内全部记录的最窄偏差范围。

## 业务模块

| 模块 | 用途 |
|---|---|
| 计量值班台 | 查阅业务口径、当班流程及最新运行。主管可核对审计记录。 |

| 同轮比对重算 | 选择批次并提交后台计算；可选择「接续上次结果」只重算受影响的组。 |
| 偏差区间 | 查看组状态、每台器具的上下界与区间宽度、冲突记录；中断恢复后整体替换。 |
| 区间复核 | 对待处理或已完成记录提交复核与处置。 |
| 结果归档 | 下载每次运行的结果 CSV。 |

## 演示数据

种子脚本导入两个同属 R1 轮的批次，便于演示增量重算：

- **澄岭计量室 R1 同轮比对批次**（发布批次）：5 个组。
  - G001 由 STD-01 锚定，QC-201、QC-202 有确定区间。
  - G002 是 QC-203 与 QC-204 互比，没有标准器，待核。
  - G003 三条记录首尾相接形成负环，整组矛盾隔离，冲突记录为 CMP-005/006/007。
  - G004 由 STD-03 锚定。
  - G005 由 STD-04 锚定，两个批次内容一致。
- **澄岭计量室 R1 同轮比对修订批次**（上游更正）：CMP-001 更正差值；CMP-002/003/005/008 撤回；新增 CMP-009/010 把 G002 与 G004 并组；CMP-011 未变。

## 演示流程

1. 以发布批次执行一次「同轮比对重算」，得到 G001、G004、G005 已解，G002 待核，G003 矛盾隔离。
2. 在「同轮比对重算」页选择修订批次，并把「接续上次结果」指向上一步的运行。
3. 结果页显示每组变更：G001 拆分更正、G002 合并、G003 更正后矛盾消除并解出区间、G004 撤回、QC-202 拆出为新的待核组 G006；G005 未变化，沿用上次结果。
4. 矛盾组在「组状态与隔离说明」和「冲突记录」中列出冲突的记录编号。
5. 运行过程中结果页保留上次已发布结果，全部组完成后一并替换；若后台中断，运行会从已完成的组继续。

## 计算口径

- 每条比对记录给出差值 d 与容差 t，表示 |(x_A − x_B) − d| ≤ t；x 为器具偏差。
- 标准器具的偏差固定为零；同一组内多台标准器具一并锚定为零。
- 把每条记录拆成两条差分约束 x_A − x_B ≤ d + t、x_B − x_A ≤ t − d，用 Bellman-Ford 最短路求上下界：
  - 上界 = 自基准出发的最短路；下界 = 到基准最短路取负；两者之差为区间宽度。
  - 无矛盾时区间内任意取值都可同时满足全部记录，因此是最窄范围。
- 组内出现负环即为矛盾，整组隔离，并列出参与负环的比对记录。
- 组内没有标准器具时无法锚定绝对偏差，标记待核；未参与任何比对的器具同样待核。
- 增量重算：按比对记录编号、器具编号与参数对比上次结果的组指纹，仅重算内容变化的组。
  - 成员集合不变而内容变化记为「更正」；成员变少为「拆分」、变多为「合并」；组号沿用原编号。
  - 上次存在而本次消失的组号按「撤回」保留在结果中。
- 中断恢复：每算完一组写入 `runs.progress`；租约被接管后当前进程不发布结果，重领的进程从已完成组继续，全部完成后一次性写入 `result`。
- 未接续上次结果的运行独立计算全部组。

## 本地开发

| 组件 | 实现 |
|---|---|
| 前端 | Nginx 与原生 HTML、CSS、JavaScript。`frontend/src/pages` 放页面，`components/common` 放共用表格、图表及表单。 |
| API | Python 3.11、FastAPI、SQLAlchemy。`backend/src/domain` 放字段、业务计算和演示数据，`routes` 放接口，`models` 放表模型。 |
| 后台 | 独立 Python worker，通过 Redis 唤醒，从数据库租约领取计算，CSV 写入共享卷。 |
| 数据 | MySQL 8 存储批次、运行与审计。`backend/scripts/seed_demo.py` 可安全重复执行。 |

领域逻辑有单元测试，可在本地直接运行（无需数据库）：

```bash
cd backend && python -m unittest discover -s tests
```

改动前端后执行 `docker compose up -d --build frontend`。改动接口或算法后执行 `docker compose up -d --build backend worker`，再刷新浏览器。如需保留数据，停止时执行 `docker compose down`。使用 `docker compose down -v --remove-orphans` 会清除该项目的数据库、Redis 和报表卷。

`.env.example` 中的 `COMPOSE_PROJECT_NAME`、`FRONTEND_PORT`、`BACKEND_PORT`、`DB_PORT`、`APP_SUBNET` 控制项目隔离。`DB_PASSWORD`、`JWT_SECRET` 和 `SEED_DEMO` 为本机演示默认设置。后端 `constants/enums.py` 与前端 `src/constants/enums.js` 保持角色、运行状态和复核状态一致。项目许可证见 `LICENSE`。
